# Forge Roadmap

This roadmap contains future work and the evidence needed to complete it.
[Architecture](ARCHITECTURE.md) describes what exists today; historical run records
belong in [Research](RESEARCH.md).

## Open creation harness

The [open creation implementation plan](roadmap/game-generation.md) is the working
sequence. Ordinary Luau source packages provide open-ended behavior; optional recipes
provide convenient lowerings and stronger scoped checks. The core requires no genre,
round, countdown, reset, UI or world topology. It separates design admission, exact
editor authority, runtime behavior and evidence. The composition IR, compiler,
creator workflow cutover and checkpoint orchestration are implemented with offline
coverage. Native installation, recovery, performance and creator-quality evidence
remain release work.

Required composition work supports arbitrary project content with stable identities,
explicit shared dependencies, independently owned instances and reviewed overrides.
Novel content composed from admitted capabilities needs no new host recipe or kit
membership. Curated content libraries are optional product expansion, excluded from
core completion criteria. General reuse, safe updates and incremental compilation
remain engineering work; catalog size is not a progress measure.

## 1. Validate the complete creator workflow

Exercise first link, read-only planning, accept/change/reject, automatic Build and
Apply, one final response, optional Play, and multiple follow-ups on the same saved
project. Include reopen, rename, save-copy, explicit fork, and publication continuity.

Completion requires current-build Studio evidence, preserved project/conversation
identity, and no duplicate outcomes or unresolved transaction inventory. Run the
orbital seed through its full interaction sequence and review HUD fit on desktop,
short windows, and phone-sized viewports. Static checks alone do not close this work.

## 2. Measure and reduce build latency

Collect repeated comparable tasks with the same prompt, model, reasoning, and
20-minute response deadline. Separate model time, preparation, tools, transport,
Apply, and final publication. Record request count, request-size breakdown, reported
input/output/reasoning/cache usage, and cost.

Prioritize redundant context, unnecessary model round trips, repeated inspection,
and long artifact serialization before changing reasoning depth or limits. Accept
an optimization only when it preserves output quality, approved scope, source
context, and transaction verification. Report distributions rather than one fast run.

## 3. Prove long-conversation continuity

Exercise enough turns to trigger multiple automatic compactions. Check that goals,
corrections, preferences, unresolved work, important references, and recent messages
survive. Include failed compaction, restart, source changes, and follow-ups after Play.

Completion requires usable continuation without silent transcript truncation,
invented approval, lost source authority, or repeated completed work.

## 4. Expand recovery and interaction coverage

Test interrupted provider responses, delayed Studio acknowledgements, Apply-time
edits, reconnects, closed recordings, and malformed passive diagnostics. Verify that
each case preserves the original cause and exposes only actions supported by current
evidence. Keep reading position, drafts, keyboard navigation, and activity expansion
stable during rapid updates and errors.

Promote reproducible defects into focused regressions. Avoid tests that merely
repeat constants or implementation steps without checking observable behavior.

## 5. Broaden capability coverage deliberately

Add classes, properties, source tools, and engine containers only with complete
host/plugin validation, canonical values, preflight, writing, reading, and replay
coverage. Keep catalog coverage distinct from authoring permission. Evaluate asset
search/import only with explicit ownership, provenance, and review requirements.

## Later product work

- User-run evidence for multiple durable checkpoints and explicit recovery.
- Reviewed failure mining and behavioral regression promotion from retained runs.
- Calibrated qualitative evaluation without overstating machine judgments.
- Automatic Rojo ownership discovery that preserves one writer per change set.
- Isolated non-Studio workers and deployment boundaries justified by measured needs.
- Optional editable content libraries when creator demand and measured quality or
  authoring cost justify them; no curated-kit prerequisite for open creation.
- Cloud identity, shared projects, and multi-user collaboration.

These are roadmap items, not current capabilities. Each needs a concrete user flow,
a bounded contract, and an evidence-producing acceptance test before implementation
is described as complete.
